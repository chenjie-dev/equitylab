# EquityLab 使用 qdb 行情库

> 创建日：2026-10-20。同级仓库 `../qdb`（本机路径）提供引擎与 HTTP；本仓库负责采集写入与只读消费。

## 保持与 qdb 最新用法一致（必做）

本文与 `collector` / research / market-data 代码只是 **EquityLab 侧落点说明**，**不是** qdb 契约的权威来源。qdb 手册会就地更新、不另建日期副本。

改行情读写、升级 `../qdb`、或怀疑本仓用法过时之前，**先读同级仓最新手册**，再对照本仓：

1. 打开 `../qdb/docs/manual/index.md`（总入口）。  
2. 至少核对：`server.md`（HTTP + **`GET /v1/ws`**）、`limits.md`、`data-model.md`、`concepts.md`、`sql.md`（`snapshots` / `ticks` / `klines`）。  
3. 若本仓仍用旧路径、旧字段，或未跟上已稳定的推送（WebSocket `SELECT … SUBSCRIBE`），**先改 collector / 读路径 / 前端，再改本文**，不要以本文覆盖 qdb 手册。  
4. Compose 镜像构建自 `../qdb`；拉新代码后需 `docker compose up -d --build qdb collector market-data frontend` 再冒烟。

权威顺序：`../qdb/docs/manual/*` → 本文件 → `2026-10-16-ashare-adata.md` / `2026-10-16-binance-market.md`。

## 职责划分

```text
公开上游（新浪 / 币安 REST / Ondo bapi）
        │
        ▼
collector（定时爬取，唯一回源）
        │  POST /v1/quotes · /v1/trades · /v1/docs
        ▼
qdb（QDB_FEED=0）
        │
        ├─ REST GET snapshots / klines / docs ─► research · market-data
        └─ GET /v1/ws（SELECT … SUBSCRIBE）──► market-data /qdb/ws 代理 ─► 前端
```

| 角色 | 目录 / 服务 | 做什么 |
|---|---|---|
| 行情库 | Compose `qdb` | 持久化 + `GET /v1/ws` 推送；**不**拉上游 |
| 客户端包 | `packages/qdb-{py,ts,rs}` | **唯一**业务侧 qdb 入口；见 [qdb-client-design](./2026-10-20-qdb-client-design.md) |
| 采集 | `services/collector` | 经 `equitylab_qdb` 写入；币安 WS→qdb |
| 读 REST | research / market-data | 经客户端只读 `QDB_URL` |
| 订阅读 | market-data `/qdb/ws` | 代理到 qdb `/v1/ws`；前端经 `@equitylab/qdb` 订阅 |
| 前端 | `/markets` · `/markets/ashare` | 当前标的订 `snapshots`；列表低频 REST |

**禁止直连 qdb：** 业务代码（apps / services 内业务逻辑）不得自行 HTTP/WS 打 qdb；新用法一律先扩 `packages/qdb-*`。  
另禁：研究层或 market-data 在读路径上直连新浪、币安 REST/WS、Ondo bapi；`/binance/v3/{*}` 与 `/binance/ws` 已拒绝上游。浏览器不直连 qdb 端口；订阅读只经 `/qdb/ws`。

## Compose 与环境

| 变量 | 默认 | 说明 |
|---|---|---|
| `QDB_URL` | `http://qdb:9090` | research、market-data、collector |
| `QDB_PORT` | `9090` | 宿主机映射 |
| `QDB_FEED` | `0` | 关掉 qdb 内置新浪采集；由 collector 写 |
| `QDB_FEED_CODES` / `COLLECTOR_CODES` | 茅台等 10 只 | A 股采集列表 |
| `COLLECTOR_INTERVAL_MS` / `QDB_FEED_MS` | `500` | **A 股** REST 热路径间隔；币安实时走 WS |
| `BINANCE_WS_URL` / `BINANCE_WS_FALLBACK` | data-stream / stream.binance.com | collector 订币安公开流写 qdb |
| `NEXT_PUBLIC_MARKET_WS_URL` | `ws://localhost:3002` | 前端订 qdb 的 WS 基址 |
| `BINANCE_REST_URL` / `BINANCE_RWA_BASE_URL` | 见 `.env.example` | **仅** collector 回源 |

数据卷：`equitylab-qdbdata` → 容器 `/var/lib/qdb`。健康检查用 `GET /v1/snapshots`（始终 200）。闲置时 `GET /health` 可能 503（心跳超过约 2s 无写入属正常）。

## 符号与周期

| 市场 | 符号 | 说明 |
|---|---|---|
| 沪市 | `SSE:600519` | 代码 5/6/9 开头 → SSE，否则 SZSE |
| 深市 | `SZSE:000001` | |
| 币安现货 | `BINANCE:BTCUSDT` | |
| Ondo 代币化美股 | `ONDO:AAPL` | ticker 大写，勿对非数字代码 `zfill` |

价格按 **10000** 倍存 `i64`（`PRICE_SCALE`）。读接口返回的 K 线价格已除以 scale。

原生周期：`1s` `1m` `5m` `15m` `1h` `4h` `1d`。前端常见的 `3m`/`30m`/`1w`/`1M` 等由读路径折叠，不原生落库。

## 写入（collector）

启动顺序：后台 **backfill**（可用 `BINANCE_KLINE_BACKFILL=0` / `COLLECTOR_SKIP_ASHARE=1` 关掉，避免占住引擎锁）；币安 **WS** 写 docs（报价/成交写入可用 `BINANCE_WS_WRITE_*=0` 关掉）；A 股按 `COLLECTOR_INTERVAL_MS` REST。历史成交必须按时间从旧到新；当前桶已打开后，更早的 trade 会被 late-tick 丢弃——因此 **Spot 图表历史走 docs**，不要指望事后回补 trades 填满 K 线。

**写路径门闸**（`services/collector/write_gate.py`）：进程内单线程刷盘；现货 / A 股 `priority=high`，RWA `priority=low`。docs 按 key 合并；quotes 先于 trades 发出，保证 snapshots 订阅读不被 RWA 单条 POST 饿死。调优：`QDB_WRITE_FLUSH_MS`（默认 25）、`RWA_BOARD_FLUSH_SEC`（默认 1.5，全量 `rwa:board` 覆盖节流）、`RWA_ENGINE_QUOTES_HOT_ONLY=1`（仅 `RWA_TICKERS` 写引擎 quotes）。**不要**再为「防饿死」默认关掉 `BINANCE_WS_WRITE_QUOTES`——关掉后现货 snapshots 为空，前端 last 只能靠 REST docs，体感会「很慢」。

节奏：

| 频率 | 动作 |
|---|---|
| 币安 WS（~50ms 合并） | `bookTicker`/`trade`/`ticker` → 高优先 quotes（先）+ trades；可选关 `BINANCE_WS_WRITE_*` |
| 币安 WS（~200ms 合并） | `depth20@100ms` / trades / 24hr ticker → 高优先 `POST /v1/docs` |
| 币安 REST K 线 feed | `binance:kline:{SYMBOL}:{interval}` docs（默认不写 trades；`BINANCE_KLINE_WRITE_TRADES=1` 才喂引擎） |
| A 股每 tick（默认 500ms） | 高优先 `POST /v1/quotes` + 量增量 trades（可 `COLLECTOR_SKIP_ASHARE=1`） |
| WS 断流 | 币安回落 REST ticker/depth（与热/慢路径相同） |
| RWA 扫盘 | 并行拉上游，**按 chunk 批量**低优先 docs/quotes；`rwa:board` 节流覆盖；冷门默认不写引擎 quotes |

| 写入 | 用途 |
|---|---|
| `POST /v1/trades` | OHLC 拆成微成交还原引擎 K 线；A 股 / 可选币安；受 late-tick 约束 |
| `POST /v1/quotes` | 实时快照 → SQL `snapshots`（**前端订阅读跟这条**；现货热门条/列表 last） |
| `POST /v1/docs` | UI 载荷（盘口、成交、ticker、**现货/RWA K 线历史**）；**不进 WS**，前端 REST 读 |
| `POST /v1/trades` | 引擎 K 线 → `klines SUBSCRIBE` 尾刷（`BINANCE_WS_WRITE_TRADES=1` 时） |

常用 docs key：

| key | 内容 |
|---|---|
| `binance:ticker:{SYMBOL}` | 24hr ticker JSON |
| `binance:depth:{SYMBOL}` | 盘口 |
| `binance:trades:{SYMBOL}` | 最近成交 |
| `binance:kline:{SYMBOL}:{interval}` | 现货 K 线 REST 原文（`{data:[[ms,o,h,l,c,v],…]}`）；**Spot 图表主源**；每 key **覆盖**写入，只留最近 `BINANCE_KLINE_LIMIT`（硬顶 500）根 |
| `rwa:stocks` | 代币化美股列表 |
| `rwa:status` | 市场状态 |
| `rwa:dynamic:{chain}:{contract}` | dynamic 原文 |
| `rwa:quote:{TICKER}` | 前端 quote 形状 |

docs 在 qdb **进程内存**中；重启 qdb 后需等 collector 再写。K 线与报价走 WAL，可恢复。

### 保留策略（禁止无限堆积）

| 数据 | 上限 | 机制 |
|---|---|---|
| `binance:kline:*` / `rwa:kline:*` | **≤15 天**（`QDB_RETENTION_DAYS`）且根数硬顶 | 写入时按开盘时间裁剪；collector `qdb-retention-gc` 每小时（`QDB_RETENTION_GC_SEC`）重写超龄 docs |
| `binance:kline:*` 根数 | ≤500（默认 180） | REST 拉取后裁尾，整 key 覆盖 |
| `rwa:kline:*` 根数 | ≤300（默认 200） | 同上 |
| `binance:trades:*` | 50 笔 | WS `deque(maxlen=50)` |
| `binance:depth:*` | 20 档 | 流本身 + 写入再裁 |
| 前端图表缓冲 | Spot ≤500 / Stocks ≤300 | 左滑合并后 `slice` 丢最旧 |
| A 股 / 币安回填 trades | 仅 ≥ 保留窗 | `cutoff_ns`；不写 15 天前 |
| 引擎 WAL（ticks / 聚合 klines） | **本版 qdb 无删除 API** | 无法按日 purge；依赖少写历史 + 运维换卷。docs 是图表历史主源 |

默认：`QDB_RETENTION_DAYS=15`，`QDB_RETENTION_GC_SEC=3600`。

## 读取

| 消费者 | 读法 |
|---|---|
| research A 股 | `GET /v1/snapshots`、`GET /v1/klines`；K 线 `view=history\|realtime\|merged` |
| market-data 币安 | docs → ticker/depth/trades；klines **优先** `binance:kline:*` docs，缺省再读引擎聚合 |
| market-data RWA | docs → stocks/status/dynamic/quote；klines → `{data:{klineInfos}}` |
| 前端实时价 | `ws://localhost:3002/qdb/ws` → qdb `GET /v1/ws` |

### 前端订阅（qdb WebSocket）

权威细节见 qdb `docs/manual/server.md` 的 `GET /v1/ws`。本仓代理：`GET /qdb/ws`（别名 `/exchanges/qdb/ws`）。

1. 浏览器连 `ws://localhost:3002/qdb/ws`（或 `NEXT_PUBLIC_MARKET_WS_URL`）。  
2. 握手后发一条文本 SQL，例如：

```sql
SELECT symbol, last, bid_px1, ask_px1, seq
FROM snapshots
WHERE symbol = 'BINANCE:BTCUSDT'
SUBSCRIBE
```

3. 先收 `{"type":"snapshot","columns":[...],"rows":[...]}`，再收 `{"type":"row","values":[...]}`；`last` 等为 scale=10000 整数，前端除以 10000。  
4. 一条连接一条 `SELECT`；现货台 / A 股台只订**当前选中标的**。列表与 24hr 字段仍 REST docs。  
5. docs（盘口、ticker JSON）**不会**从 `/v1/ws` 推送。

缺 docs 时 HTTP 返回空盘口/空列表，不 502，便于采集尚未完成时 UI 仍可打开。

### 读路径零外呼（强制）

**一句话：** 除 `services/collector` 外，任何读路径不得对公开行情上游发 HTTP/WS；缺数据空/503，等 collector 补写。

| 允许 | 禁止 |
|---|---|
| market-data / research / frontend 读 qdb（经 `packages/qdb-*` 或 market-data `/qdb/ws`） | 读路径 `reqwest`/`requests`/`fetch`/`tokio-tungstenite` 打币安、新浪、AlphaFeed、其它公开行情 |
| collector 回源写入（唯一外呼面） | market-data 代理透传上游（`/v3/{*}`、`/binance/ws`、RWA bapi） |
| 前端由 qdb K 线本地算 MA/BOLL/MACD | 前端为指标再拉外部接口；浏览器直连币安/新浪 |

权威条文见根目录 [`AGENTS.md`](../AGENTS.md) §7–§8。

## 冒烟

```bash
# qdb 直连
curl -s 'http://localhost:9090/v1/snapshots?symbols=SSE:600519' | head -c 300
# 窗口读（limit / endTime=ms），避免一次拉全历史
curl -s 'http://localhost:9090/v1/klines?symbol=BINANCE:BTCUSDT&period=1h&limit=200' | head -c 200
curl -s 'http://localhost:9090/v1/docs?key=binance:ticker:BTCUSDT' | head -c 200

# 经业务层（只读 qdb）
curl -s 'http://localhost:3000/api/research/ashare/quotes?codes=600519' | head -c 200
curl -s 'http://localhost:3000/api/market/binance/ticker/24hr?symbol=BTCUSDT' | head -c 200

# WS（需 websocat）：先连代理再发 SELECT
# websocat ws://localhost:3002/qdb/ws
# 然后输入：SELECT symbol, last FROM snapshots WHERE symbol = 'BINANCE:BTCUSDT' SUBSCRIBE
```

## 排障

| 现象 | 处理 |
|---|---|
| 报价/盘口突然空 | qdb 刚重建，docs 丢了；看 `docker logs equitylab-collector` 是否在 poll |
| K 线只有几根 | 曾在 backfill 前写过 live trade；必要时重建卷 `equitylab-qdbdata`（会丢历史） |
| collector 解析不了 `qdb` | 换过网络后需 `docker compose up -d collector` 重建容器 DNS |
| `/health` 503 | 闲置无写入时正常；探活用 `/v1/snapshots` |
| 宿主机 9090 被占 | 关掉本机单独跑的 `qdb`，交给 Compose |
