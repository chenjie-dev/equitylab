## 1. 为何需要

流水线角色与 qdb 硬约束已有，但代理易在「代码已写」处停住，缺少**可复现证据**与**数据面闭环**（采集→qdb→读 API→UI）。本页把验收剧本写死，减少口头「好了」。

## 2. 分级与最小证据

| 级别 | 最小证据包 |

| hotfix | 复现命令变绿 + 回归相关 1 条 |

## 3. 数据面验收剧本（行情）

顺序固定：

```text
1. docker compose up -d --build collector   # 及改动的 research / market-data
2. 日志：cn_equity=N 或 binance ws open；非 cn_equity=skip
3. curl qdb snapshots / docs（目标 symbol 或 cn-equity:codes count）
4. curl gateway/research 或 market-data 读 API
5. 前端关键路径（或 BFF）目视 / 断言
```

示例（按改动裁剪）：

```bash
# A 股目录与报价
curl -s 'http://localhost:3000/api/research/cn-equity/codes?limit=1'   # 看 count / source
curl -s 'http://localhost:3000/api/research/cn-equity/quotes?codes=600519,000001'
curl -s 'http://localhost:9090/v1/snapshots?symbols=SSE:600519'

# 现货
curl -s 'http://localhost:9090/v1/snapshots?symbols=BINANCE:BTCUSDT'
# 订阅读经 market-data /qdb/ws（浏览器或 websocat）
```

**失败判定**：列表有码无价且未标明「轮询滞后/仅目录」；cn-equity 出现 BTCUSDT；换票 K 线纵轴从 0 起压扁且未修。
